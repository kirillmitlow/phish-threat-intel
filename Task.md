# Метод обобщения результатов глубокого анализа фишинговых веб-страниц и вложений в компактные признаки для локальной антиспам-фильтрации

## Цель

Разработать подход, позволяющий с помощью тяжеловесных моделей экстракторов и инструментов глубокого анализа собрать структурированную информацию о фишинговых письмах, ссылках, веб-страницах, вложениях и спам-кампаниях.

Полученная база данных должна использоваться для дальнейшего формирования сигнатур известного фишинга, выделения устойчивых признаков фишинговых писем и подготовки компактных правил, пригодных для использования в локальном антиспам-движке.

## Описание исследования

В рамках исследования предполагается разработать систему, которая будет выполнять глубокий анализ доступных компании образцов фишинговых писем и связанных с ними объектов:

- URL
- Редирект-цепочек
- Финальных вебстраниц
- HTML/DOM-структуры
- PDF/HTML/Office-вложений
- QR-кодов
- Форм ввода данных
- Визуальных элементов
- Признаков принадлежности к фишинговым кампаниям

**Задача системы** — накапливать структурированную базу знаний о фишинговых объектах.

## Два направления анализа

### Направление 1: Фишинговые ссылки

Необходимо раскрывать URL до конечного ресурса, фиксировать редирект-цепочку, анализировать:

- Финальный домен
- HTML-страницу
- DOM-структуру
- Формы ввода
- Внешние ресурсы
- Favicon
- Скрипты
- Визуальное сходство страницы с известными брендами

### Направление 2: Вложения

Необходимо извлекать из них:

- Ссылки
- QR-коды
- HTML-формы
- Встроенные ресурсы
- Другие признаки, которые могут указывать на фишинговую технику

## Базовый ориентир: Phishpedia

В качестве одного из базовых ориентиров может использоваться **Phishpedia** — подход к визуальному определению фишинговых веб-страниц по логотипам и соответствию между брендом, который имитирует страница, и доменом, на котором она размещена.

В рамках данной темы Phishpedia интересна **не как готовый продуктовый модуль**, а как пример тяжеловесного экстрактора, который может помогать определять целевой бренд фишинговой страницы, фиксировать признаки **brand impersonation** и наполнять базу данных информацией о том, какие бренды, визуальные шаблоны и доменные несоответствия используются в фишинговых кампаниях.

## HTML/DOM-признаки

Дополнительно необходимо использовать экстракторы HTML/DOM признаков. Они должны позволять извлекать:

- Структуру страницы
- Наличие форм ввода логина и пароля
- `form action`
- Внешние скрипты
- `iframe`
- Признаки обфускации
- Повторяющиеся DOM-шаблоны
- Сходство с известными phishing kits

## Ожидаемый результат

Результатом работы должен стать **прототип пайплайна**, который:

1. На вход принимает фишинговые образцы и связанные с ними объекты
2. Прогоняет их через набор тяжеловесных моделей-экстракторов
3. Сохраняет результаты анализа в структурированную базу данных
4. Формирует на её основе компактные артефакты для дальнейшего использования:
   - Сигнатуры
   - URL и DOM-шаблоны
   - Правила для вложений
   - Brand-based признаки
   - Fingerprints
   - Reason codes

## Критерии оценки качества

Качество решения предполагается оценивать по нескольким направлениям:

1. Насколько полно система извлекает информацию из ссылок, веб-страниц и вложений
2. Насколько полезны собранные данные для создания сигнатур
3. Насколько хорошо компактные признаки переносятся в лёгкий антиспам-движок
4. Насколько они устойчивы к изменению доменов, URL и внешнего оформления фишинговых страниц
5. Насколько полученные reason codes помогают объяснить решение системы

## Важное замечание

> Особое внимание следует уделить тому, чтобы результат не сводился только к списку заблокированных URL или доменов. Более важной задачей является накопление информации о повторяющихся фишинговых техниках и шаблонах:
> - Имитация брендов
> - Credential forms
> - QR-phishing
> - HTML attachments
> - Подозрительные редиректы
> - Reuse HTML/DOM-шаблонов
> - Похожие landing pages
> - Признаки принадлежности к одной кампании

## Смежная тема прикладного характера

### Разработка внутреннего phishing intelligence pipeline

Для подготовки сигнатур и компактных признаков локального антиспам-движка. Модуль должен:

1. Анализировать доступные компании образцы фишинговых писем, ссылок, веб-страниц и вложений
2. Извлекать из них признаки с помощью тяжеловесных моделей и специализированных экстракторов
3. Сохранять результаты в структурированную базу данных
4. Использовать её для генерации сигнатур, правил и признаков, применимых в локальной антиспам-фильтрации
